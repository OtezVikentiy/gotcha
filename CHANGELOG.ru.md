# Changelog

Все значимые изменения в этом проекте документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), и
проект намерен придерживаться [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
после начала выпуска релизов с тегами.

## [Unreleased]

### Added

- **Оверлей деплоя для слабого железа** (`docker-compose.small.yml`) под
  минимальные серверы (2 vCPU / 2 ГБ): ограничивает память и приём событий
  ClickHouse под скромные ресурсы. На VPS 2 ядра / 2 ГБ дал память ClickHouse
  880 → 295 МБ, диск 12 → 9.2 ГБ, load average 1.15 → 0.79. Применять только на
  слабом железе — на сервере с запасом он бы душил приём событий.

### Fixed

- **График задержки в аптайме** теперь с осями, шкалой в миллисекундах,
  метками времени, легендой фаз (DNS/TCP/TLS/TTFB) и подсказками по часам.
  Шкалу задают отрисованные тайминги фаз, а не средний total, поэтому один
  таймаут проверки больше не схлопывает здоровые столбики в нечитаемую полоску;
  часы выше шкалы помечаются меткой, а в подсказке виден реальный total.
- **Полоска доступности** получила отдельное «частичное» (жёлтое) состояние:
  монитор, который в основном здоров, но иногда ловит сбои, больше не красится
  целиком в красный — 90 %-аптайм читается как «иногда постреливает», а не «лежит».
- Упрочнён разбор целочисленных значений в конфиге и версий миграций
  (парсинг с ограничением разрядности) — закрывает предупреждения CodeQL о
  небезопасной конверсии. Поведение не меняется: источники — доверенный
  env-конфиг оператора и имена встроенных файлов миграций.
- У системных логов ClickHouse появился TTL, а планировщик PostgreSQL считает
  стоимости под SSD — универсальные дефолты в базовом compose; раньше диск под
  системными логами ClickHouse рос без ограничения на любом железе.

## [0.1.0] - 2026-07-22

Начальный набор возможностей self-hosted релиза:

### Added

- **Проблемы / трекинг ошибок**: приём событий, совместимый с Sentry SDK,
  автоматическая группировка в проблемы (issues), стек-трейсы, хлебные крошки
  (breadcrumbs), теги/контексты.
- **Производительность / трейсинг**: распределённые трейсы и транзакции, Web
  Vitals, обнаружение проблем производительности и обнаружение регрессий.
- **Метрики**: приём метрик OTLP, запросы по метрикам, правила оповещений по
  порогам и инциденты.
- **Профилирование**: профили CPU/флеймграфы из payload'ов профилирования Sentry
  и pprof, с обнаружением регрессий профилей.
- **Мониторинг аптайма**: HTTP-проверки из встроенного локального региона или с
  удалённых проб (`--mode=probe`), обнаружение инцидентов, публичные страницы
  статуса.
- **Оповещения**: доставка по email, вебхуку и в Telegram; правила для новых
  проблем, всплесков, порогов по метрикам и регрессий производительности/аптайма.
- **Организации, команды и RBAC**: мультитенантные организации, проекты и роли
  участников.
- **SSO**: вход через generic OIDC, Yandex ID и VK ID, каждый настраивается
  независимо.
- **Значения по умолчанию для приватности и безопасности**: серверная очистка
  PII (обнуление IP/email, редактирование по ключам) и защита от SSRF для
  исходящих запросов вебхуков/аптайма, обе включены по умолчанию.
- **Настраиваемый срок хранения** по каждому типу сигнала (события/транзакции,
  спаны, метрики, профили) через TTL ClickHouse.
- **Настройки производительности на уровне проекта** и переопределения срока
  хранения спанов.
- Развёртывание одним бинарником (`gotcha`) с
  `--mode=ingest|web|uptime|probe|all`.
- Документация внутри продукта (`/docs`) на английском и русском.
- Файлы open-source проекта: README, LICENSE (Apache-2.0), CONTRIBUTING,
  SECURITY, CODE_OF_CONDUCT, `.env.example`.
- Версия сборки в подвале интерфейса, на странице «О программе», в
  `--version` и `/version`.
